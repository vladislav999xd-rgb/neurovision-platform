# Подготовка к защите: электронная регистратура

Материал ниже сверен с файлами `student_logic.py` и `app.py`. Домашняя функция
`room_message()` в командной версии не реализована.

## Объяснение проекта за 30 секунд

Регистратура хранит талоны в списке словарей. У каждого талона есть номер, код
условного посетителя, кабинет, статус и порядок в очереди. Программа умеет
зарегистрировать талон, вызвать следующего посетителя, завершить или отменить
обращение и отобрать записи по трём условиям. Предметные правила находятся в
`student_logic.py`, а формы и кнопки Streamlit — в `app.py`.

## Алёна: данные и регистрация

1. **Как устроен один талон?** Это словарь с ключами `id`, `visitor_code`,
   `cabinet`, `status` и `queue_order`.
2. **Что возвращает `make_initial_records()`?** Новый список из шести
   исходных талонов. Поэтому одна проверка не портит данные следующей.
3. **Зачем нужны `strip()` и `upper()`?** Первый метод убирает краевые
   пробелы, второй превращает `p107` в `P107`.
4. **Как проверяется код?** Его длина равна четырём, первый символ — `P`, а
   следующие три символа являются цифрами.
5. **Когда повтор запрещён?** Если у того же кода уже есть `waiting` или
   `in_service` в том же кабинете.
6. **Как получаются новые номера?** Цикл находит наибольшие `id` и
   `queue_order`, после чего прибавляет один.

Пошаговый пример: `register_ticket(tickets, " p107 ", "101")` очищает код,
получает `P107`, проверяет кабинет и повторы, находит максимальные значения 6 и
добавляет талон с номером и порядком 7.

Небольшое изменение для тренировки: заменить текст успешного сообщения. Данные
талона и правила регистрации от этого не меняются.

## Влад: очередь и статусы

1. **Чем отличаются `waiting` и `in_service`?** Первый статус означает
   ожидание, второй — посетитель вызван и занимает кабинет.
2. **Почему вызов в кабинет 102 отклоняется?** Там уже находится талон 3 со
   статусом `in_service`.
3. **Как определяется первый ожидающий?** Среди `waiting` выбранного кабинета
   находится наименьший `queue_order`.
4. **Почему в кабинет 101 вызывается талон 1?** Его порядок равен 1, а у
   второго ожидающего талона порядок равен 2.
5. **Какой талон разрешено завершить?** Только `in_service`.
6. **Какой талон разрешено отменить?** Только `waiting`; запись не удаляется.

Пошаговый пример: `call_next(tickets, "101")` сначала убеждается, что кабинет
свободен, затем сравнивает ожидающие талоны 1 и 2 и меняет только статус талона
1 на `in_service`.

Небольшое изменение для тренировки: изменить сообщение «Кабинет занят», не
меняя условие проверки статуса.

## Хеда: фильтры и проверки

1. **Что делает `select_tickets()`?** Создаёт новый список подходящих записей.
2. **Какие условия можно указать?** Кабинет, статус и часть кода посетителя.
3. **Как работают несколько условий?** Талон должен пройти каждое непустое
   условие одновременно.
4. **Почему `p10` находит `P101`?** Оба текста перед поиском сравниваются без
   учёта регистра.
5. **Изменяет ли фильтрация талоны?** Нет, она только добавляет ссылки на
   подходящие словари в новый список.
6. **Почему перед каждой проверкой создаются новые данные?** Чтобы предыдущие
   изменения статусов не влияли на следующий ожидаемый ответ.

Пошаговый пример: для условий `101`, `waiting`, `p10` цикл пропускает записи
других кабинетов и статусов, а в результат добавляет талоны 1 и 2.

Небольшое изменение для тренировки: выбрать в интерфейсе статус `done` и
объяснить, почему полный список не изменился, хотя таблица поиска стала короче.

## Ира: поиск и интерфейс

1. **Что делает `find_ticket()`?** Сравнивает переданный номер с полем `id` и
   возвращает найденный словарь или `None`.
2. **Почему нельзя использовать `tickets[3]` для поиска талона 3?** Индексы
   начинаются с нуля, поэтому это выражение выберет четвёртую запись.
3. **Для чего нужен `st.session_state`?** Он сохраняет один список между
   обычными нажатиями в текущем сеансе браузера.
4. **Почему логика отделена от Streamlit?** Функции можно проверить простыми
   вызовами без браузера, а интерфейс только передаёт им данные.
5. **Как выбирается талон для завершения или отмены?** Пользователь явно
   выбирает его `id` из результатов поиска.
6. **Зачем в выборе есть пункт «Выберите талон»?** После смены фильтра нельзя
   незаметно применить действие к первой попавшейся записи.

Пошаговый пример: при выборе номера 3 интерфейс вызывает `find_ticket`,
показывает код и статус, а кнопка «Завершить обращение» передаёт именно число 3 в
`finish_ticket`.

Небольшое изменение для тренировки: поменять подпись кнопки «Завершить обращение» и
объяснить, почему вызываемая функция остаётся прежней.

В таблице статусы показаны по-русски для удобства, но в самих словарях остаются
служебные значения `waiting`, `in_service`, `done` и `canceled`.

## Что должны знать все участники

- `list` хранит несколько записей в порядке очереди.
- `dict` хранит поля одной записи по именам ключей.
- `for` по очереди просматривает элементы списка.
- `if` проверяет условие до изменения данных.
- `return` завершает функцию и отдаёт результат.
- `None` означает, что талон не найден или ещё не выбран.
- `append()` добавляет новый талон в конец списка.
- При отказе ни одна запись не должна измениться.
